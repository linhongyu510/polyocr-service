# 安全指南

## 凭据处置

仓库旧版本曾包含硬编码凭据。仓库所有者必须立即在对应供应商侧撤销并轮换这些凭据，
检查访问记录，并确认旧值不再拥有任何权限。当前树已删除已知值，但普通提交无法从 Git
历史、已有分支、分叉或克隆中抹除它们。

是否使用 `git filter-repo` 重写公开历史须由仓库所有者评估。历史重写会改变提交 SHA，
需要协调所有协作者和下游克隆，因此本次工程改造不自动执行。

## 运行配置

- 通过环境变量或秘密管理器注入 `POLYOCR_API_KEY` 和翻译供应商密钥。
- 不要把 `.env`、日志、请求体、模型缓存或客户文档提交到 Git。
- 对外部署时启用认证、TLS、上传大小限制和反向代理限流。
- CORS 使用明确来源；启用凭据时不得配置通配符来源。
- 日志只记录请求 ID、状态码和必要的运行指标，不记录密钥或上游响应正文。

## 报告问题

安全问题不应附带真实密钥、个人数据或客户文档。请通过仓库所有者指定的私密渠道报告；
在正式渠道建立前，不要创建包含可利用细节的公开 Issue。
